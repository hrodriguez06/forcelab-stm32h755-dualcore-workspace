Benchmark B1: Baseline HSEM Timing and Retention Measurements (Phase F0)
Target: NUCLEO-H755ZI-Q (STM32H755ZI Silicon Rev V, ID 0x450)
Date:   Sep 26, 2026

1. Raw Peripheral Operation Timing (Hardware Register Access via DWT CYCCNT)
----------------------------------------------------------------------------
Measurements taken directly with DWT CYCCNT running on each core:

- Cortex-M7 (CPU1 @ 400 MHz):
  * FastTake (1-step read of HSEM_RLRx):  16 cycles  (40.0 ns)
  * Take (2-step write HSEM_Rx + readback): 30 cycles  (75.0 ns)
  * Release (write HSEM_Rx with LOCK=0):    3 cycles   (7.5 ns)

- Cortex-M4 (CPU2 @ 200 MHz):
  * FastTake (1-step read of HSEM_RLRx):   8 cycles  (40.0 ns)
  * Take (2-step write HSEM_Rx + readback): 24 cycles  (120.0 ns)
  * Release (write HSEM_Rx with LOCK=0):    6 cycles   (30.0 ns)

Analysis:
- The bus access to HSEM (in D3 domain via AHB4) takes ~40 ns for a read from
  either core, which corresponds to 16 cycles on the 400 MHz M7 and 8 cycles
  on the 200 MHz M4.
- A 2-step take requires an AHB write followed by an AHB readback, taking ~75 ns
  on CM7 and ~120 ns on CM4.
- A release is a single 32-bit write, buffered on AHB (3 cycles on CM7, 6 on CM4).

Application hold times of HSEM 4 were not measured in F0. They were measured
later with committed DWT instrumentation; see 01_shared_drivers/10_hsem/README.md
section 11.2 (CM7 42.7 us, CM4 37.6 us).

3. Debugger RLR Read Pitfall Verification
-----------------------------------------
- SWD Hotplug read of 0x58026480 (HSEM_RLR[0]):
  Returned: 0x80000300 (LOCK=1, COREID=3, PROCID=0).
  Immediate read of 0x58026400 (HSEM_R[0]):
  Returned: 0x80000300 (SEMAPHORE WAS TAKEN BY DEBUGGER ACCESS PORT).
  Conclusion: SWD memory reads of the RLR region (0x58026480 - 0x580264FC)
  take semaphores identically to CPU1. All debug dumps must read only HSEM_R
  (0x58026400 - 0x5802647C).
