1. Raw Peripheral Operation Timing (Hardware Register Access via DWT CYCCNT)
----------------------------------------------------------------------------
Measurements taken directly with DWT CYCCNT running on each core:

- Cortex-M7 (CPU1 @ 400 MHz):
  * FastTake (1-step read of HSEM_RLRx):  16 cycles  (40.0 ns)
  * Take (2-step write HSEM_Rx + readback): 30 cycles  (75.0 ns)
  * Release (write HSEM_Rx with LOCK=0):    3 cycles   (7.5 ns)

- Cortex-M4 (CPU2 @ 200 MHz):
  * FastTake (1-step read of HSEM_RLRx):   8 cycles  (40.0 ns)
  * Take (2-step write HSEM_Rx + readback): 24 cycles  (120.0 ns)
  * Release (write HSEM_Rx with LOCK=0):    6 cycles   (30.0 ns)

Analysis:
- The bus access to HSEM (in D3 domain via AHB4) takes ~40 ns for a read from
  either core, which corresponds to 16 cycles on the 400 MHz M7 and 8 cycles
  on the 200 MHz M4.
- A 2-step take requires an AHB write followed by an AHB readback, taking ~75 ns
  on CM7 and ~120 ns on CM4.
- A release is a single 32-bit write, buffered on AHB (3 cycles on CM7, 6 on CM4).

2. In-Application Semaphore Retention Duration (prj_04)
-------------------------------------------------------
- HSEM 4 (HSEM_ID_ADC_DATA):
  * CM4 Producer (adc_acquisition.c):
    Guards waveform update (512 samples = 1024 bytes).
    Measured duration: ~270 cycles at 200 MHz (~1.35 microseconds).
  * CM7 Consumer (adc_server.c):
    Guards telemetry copy into UDP buffer.
    Measured duration: ~260 cycles at 400 MHz (~0.65 microseconds).
  * Finding: Maximum retention under HSEM 4 is ~1.35 microseconds (CM4 memcpy).
    A spin limit of 1000 loops in Shared_TryLock on CM4 (200 MHz) covers approx
    3-5 microseconds, which barely covers the worst-case bus contention.
    Converting to a cycle-based timeout of 2000-4000 cycles ensures robust operation.

- HSEM 3 (HSEM_ID_M4_TO_M7_MBOX):
  * CM4 Producer (dma_selftest.c, main.c):
    Formats string into g_shared.m4_to_m7: ~350 cycles at 200 MHz (~1.75 us).
  * CM7 Consumer (app_main.c Status_Task - S11 Flaw):
    Status_Task held HSEM 3 across APP_LOG(), which acquires xSemaphoreTake
    and transmits over 115200 baud UART blocking.
    Measured duration: 2,500,000 to 5,000,000 cycles (~6.25 to 12.5 milliseconds)!
    This blocks CM4 in SHARED_LOCK(HSEM_ID_M4_TO_M7_MBOX) for milliseconds.
    Remediation in Phase F2: copy mailbox buffer out, release HSEM 3 immediately,
    and only then invoke APP_LOG (resolving S11).

4. Debugger RLR Read Pitfall Verification
-----------------------------------------
- SWD Hotplug read of 0x58026480 (HSEM_RLR[0]):
  Returned: 0x80000300 (LOCK=1, COREID=3, PROCID=0).
  Immediate read of 0x58026400 (HSEM_R[0]):
  Returned: 0x80000300 (SEMAPHORE WAS TAKEN BY DEBUGGER ACCESS PORT).
  Conclusion: SWD memory reads of the RLR region (0x58026480 - 0x580264FC)
  take semaphores identically to CPU1. All debug dumps must read only HSEM_R
  (0x58026400 - 0x5802647C).
