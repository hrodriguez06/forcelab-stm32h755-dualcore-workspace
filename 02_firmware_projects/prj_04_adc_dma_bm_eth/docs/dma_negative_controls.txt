DMA DRIVER ITERATION 2: NEGATIVE CONTROLS EVIDENCE LOG
================================================================================
Per Rule R1 (IMPLEMENTATION_PLAN_2.md §0), every test added or modified in
iteration 2 was subjected to a hardware negative control: the driver or test code
was mutated to reintroduce the defect, the firmware was rebuilt and flashed to the
board, and UART telemetry was captured showing the exact failure line with a
-dirty git revision. The mutation was subsequently reverted via git checkout, the
build tree was cleaned, and clean PASS was re-verified.

4. CONTROL Y4 (CM7 D-Cache coherency for DMA_LL_MemCopy)
--------------------------------------------------------

instead of PSIZE. With PSIZE=WORD (4 B) and MSIZE=BYTE (1 B), only 16 bytes were
cleaned instead of 64, causing data corruption in uncached physical RAM.
